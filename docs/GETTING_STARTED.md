# 上手：装上去、五分钟走一遍

这份文档面向**第一次拿到这个 APK 的人**。它只讲「怎么让它跑起来、看到什么算正常」，
设计取舍与实现细节见 [`../README.md`](../README.md)。

---

## 一、装上去

构建产物：`app/build/outputs/apk/debug/app-debug.apk`

```powershell
# 手机开 USB 调试后
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

也可以直接把 APK 拷进手机点安装（debug 包不需要额外签名）。

自己构建（工具链就在项目里的 `.toolchain/`，完整命令见 README 的「构建」一节）：

```powershell
$project = '<项目路径>'
$env:JAVA_HOME = "$project\.toolchain\jdk-21"

$gradle = (Get-ChildItem "$env:USERPROFILE\.gradle\wrapper\dists\gradle-8.14.3-all" `
    -Recurse -Filter 'gradle.bat' -File | Select-Object -First 1).FullName

& $gradle -p $project --console=plain --no-daemon `
    "-Dorg.gradle.java.home=$env:JAVA_HOME" :app:assembleDebug
```

最低支持 Android 8.0（API 26）。目标版本 36。

## 二、第一次打开会看到什么

首页是空的，顶部有一张卡片：

> **让系统自动记账**
> 授权「使用情况访问」后，手机会把各 App 的使用记录交给本应用……

这是正常的。**这款 App 的核心数据来自系统**，所以第一步是授权。

## 三、五分钟走一遍（推荐顺序）

### 第 1 步：授权「使用情况访问」

点卡片上的 **去授权** → 跳到系统设置 → 在列表里找到 **时间记账** → 打开。

> 这是**特殊权限**，没有弹窗可点，只能进系统设置手动开。
> 设置页不一定直接定位到本应用，需要自己在列表里找。
> 本应用只读取 App 的使用时长（`UsageStatsManager`），不读取任何内容。

回到首页。卡片**应该立刻变成**：

> **系统感知** ｜ 重新读取 ｜ 去归类
> 读出 N 段时间，X 段已自动归类，Y 段待确认…

- 如果写的是「已授权，但系统里还没有可用的使用记录」：
  说明授权生效了，只是系统里暂时没有数据 —— 刚授权、或者今天还没怎么用手机时就是这样。
  用一会儿手机再回来，或者点「重新读取」。
- 如果还是「去授权」：权限没给上，再进设置确认一次。

### 第 2 步：给几个常用 App 归类

点 **去归类**。会看到最近用过、但系统不知道是什么的 App，按最近使用排序。

挑最常用的几个（微信、B站、学习类 App），点 **归类** → 选分类与活动 → 保存。

> **这一步是「少记录」的开关。** 归类一次，之后这个 App 的所有记录都自动归到那一类，
> 再也不会来问你。不做这一步，时间轴上会堆着一片「未归类」，你得逐条确认。

对话框里可以**两个都不选**再保存 —— 那表示「这个 App 不用归类」，之后也不再问你。

### 第 3 步：建一个目标

首页「目标」分组 → **管理** → **新建**。例如：

| 字段 | 值 |
|---|---|
| 名称 | Java |
| 类型 | 时长 |
| 周期 | 每日 |
| 目标值 | 3（小时） |
| 分类 | 学习 |

保存后回到首页，「目标」分组会显示 `Java　0m / 3h` 和一根进度条。

### 第 4 步：看这一天

回到首页往下滑：

- **计划 vs 实际**：还没有课表时会提示「还没有课程表」（可选，见第 5 步）
- **分类时间**：系统采集到的记录按分类汇总
- **时间轴**：`14:00–14:35　微信　35m` 这样一行行列出来，**点任意一行可以改**
- **缺失时间**：没有记录的时间段

### 第 5 步（可选）：补一份课表

首页「计划 vs 实际」→ **课表** → **新建**：名称、星期、起止时间。
之后「计划 vs 实际」会告诉你「计划 1h40m，照计划做了 1h40m（100%）」。

## 四、日常怎么用

| 想做的事 | 怎么做 |
|---|---|
| 刚学完半小时，记一笔 | 首页右下角 **记一笔** → 选活动 + 时长 |
| 系统记错了时间 | 首页时间轴点那一行 → 改起止 / 分类 / 备注 |
| 系统猜的归属对不对 | 首页「待确认」旁 **去确认**，一键确认或改一下 |
| 有一段时间没记录 | 首页「缺失时间」旁 **补记** |
| 回看某一天 | 日历 Tab → 点某一天 |
| 看这周/这月花了多少时间 | 统计 Tab → 周 / 月 / 年 |

## 五、需求里那三个问题，怎么试着回答

V1 要验证三件事（需求十七节）。它们都要**真机 + 用上几天**才有答案，
下面是「怎么试」，不是「结论」。

### 1. 用户能否低成本地记录和整理一天？

- 试：日常用两三天，只在想起的时候点「记一笔」或处理「待确认」。
- 看：首页「有记录」的小时数是不是基本由系统补全的；你手动点了几次。
- 反例信号：如果一天要点十几次「确认」，说明归类没做够（第 2 步），或者推断规则太保守。

### 2. Android 系统数据能否明显减少手动记录？

- 试：第 2 步归类 3–5 个最常用的 App，然后正常用手机两天。
- 看：时间轴上「已自动归类」的段数 vs「待确认」的段数。
  归类做得越足，待确认应该越少 —— 这是这款 App 成不成立的关键。
- 反例信号：如果每天新出现的 App 都很多，说明你的手机使用很分散，
  「系统自动还原」的价值会下降（这正是需求十七节要问清楚的）。

### 3. 「计划 vs 实际」对比是否真能帮人调整安排？

- 试：先填一周课表（或用几天后补填），每天看一眼「计划 vs 实际」那一行。
- 看：你会不会因为「照计划做了 30%」而真的去改计划或改安排。
- 注意：这一条最像**产品问题**而不是技术问题 —— 数据对不对是代码保证的，
  有没有用只能靠用一段时间后的感觉。

## 六、这个版本**不做**的事（免得白找）

按需求十五节，V1 明确不含：

- 账号 / 登录 / 云同步 / 多端
- iOS
- 社交（好友、排行、分享）
- AI Agent 与复杂推荐
- GPS / 定位
- 通知内容分析
- 健康数据（步数、睡眠）
- 教务系统爬取
- 复杂 OCR

另外几件**知道但故意没做**的（README 里有决策记录）：

- 删除一条系统记录后，如果原始事件还在，下次重新分析会把它重新生成出来；
  想永久排除请改它的归属，或直接编辑它。
- 提醒用的是非精确闹钟：系统可能把它推迟几分钟 —— 提醒不是闹钟，够用即可。
