## 三、P0（必须优先，按用户给的顺序）

1. **首页视觉层级重构** —— 区块重排为：今天概览 → 当前状态 → **时间轴** → 目标 → 计划 vs 实际 → 统计。
   判断标准是「3 秒知道今天怎么样、10 秒发现问题」，不是「更好看」。
2. **当前时间线** —— `──── 当前 16:42 ────`，随时间移动；写法放在映射器里（纯函数 + 测试）。
3. **当前正在进行状态** —— 有明确活动时显示「正在进行 · Java · 已持续 42 分钟」，
   没有时显示「当前时间 · 尚未确认」。
4. **时间轴体验优化** —— 手动/系统记录的细微差异、进行中记录的轻微强调。
5. **Plan vs Actual 可视化** —— 计划轴 vs 实际轴，**突出显示偏离的那几段**，
   而不是只给一个完成率。（数据侧已经现成。）
6. **首页目标反馈** —— 「还差 40 分钟」这种可直接行动的文案。
7. **空白 / 待确认时间优化** —— 措辞再核一遍「未记录 ≠ 浪费」，并给「这段时间发生了什么？」入口。
8. **真实日程数据下完整测试** —— 目前课表里**一条计划都没有**，所以 Plan vs Actual 从未被真实数据验证过；
   这一条同时也是规格书第十七节第 3 个问题的答案。

## 七、验收标准（不是「看起来更漂亮」）

用户打开 App 后能快速回答：

- 我今天已经花了多少时间？
- 我主要把时间花在哪里？
- **我现在正在做什么？**
- 哪些时间还没有确认？
- 我的实际时间和计划有什么差距？
- 我的目标完成得怎么样？
- 和过去几天相比，我的时间结构发生了什么变化？

**如果只是多了颜色、动画、Card 和图表，而用户仍然不知道「我今天到底过得怎么样」，
那就不算成功。**

**关键教训：用 Word 版而不是 PDF 版。** PDF 的课程文字画在嵌套 Form XObject 里，
`extract_text` 的 visitor 拿不到列坐标（两种取法都试过，七列全是 0 条），所以**分不出星期几**；
同一份课表的 `.docx` 是**真表格**，单元格位置直接给出星期几，周次/场地/教师都在单元格文字里，
一次解析干净。下次要导课表，直接要 Word/Excel，别在 PDF 上耗。

**另一个必须记住的事实**：同一门课在不同星期几的周次可能**不一样**
（大学物理：周一 `第18周`、周五 `1周,4-6周,8-15周,17周`、周六 `第4周`、周日 `第1周`），
所以**不能按课程名合并**——合并就会在没课的周里谎报「计划有课」。

### 一条用血换来的规矩：不要用 PowerShell 改源码

改文件时图省事用了 `(Get-Content $f -Raw) -replace ... | Set-Content -Encoding UTF8`。
**PowerShell 5.1 的 `Get-Content` 没指定 `-Encoding` 时按系统 ANSI 解码**，于是中文注释全成乱码，
**部分换行还被吞掉**，代码行被并进上一行的 `//` 注释里 —— 报错看上去莫名其妙
（`No value passed for parameter 'source'` / `'categoryRepository'`）。

第一次坏了 `Mappers.kt` 与 `TimeLedgerDatabase.kt`：我为拆回被吞的行，把「一个没闭合的块注释
及其之后的一切」删掉，结果**丢掉了全部映射函数和 `MIGRATION_1_2`/`ALL_MIGRATIONS`**，
只能按实体与领域模型的字段逐条重写；第二次又坏了 `AppContainer.kt`。**同一个错误犯了两次。**

> **规矩**：改文件用编辑工具；要脚本化就用 **Python 显式 `encoding="utf-8"`**；
> **绝不用** PowerShell 的 `Get-Content`/`Set-Content` 做文本替换。
> 修复时**不要自动截断源码** —— 宁可停下来看编译错误。
