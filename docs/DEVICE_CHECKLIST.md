# 真机走查清单

这份清单的作用只有一个：**把 README 里所有「⏳ 需真机」变成可以逐条勾选的动作**。

本机（开发环境）没有模拟器、没有设备、也没有 Studio Preview，
所以界面观感、通知与闹钟的实际行为、`UsageStatsManager` 的真实返回
**从来没有被验证过** —— 能验证的只有「编译通过」和 571 个 JVM 用例。
拿一台 Android 手机，从上往下走一遍，就能把这三块补齐。

> 每条都写了**预期结果**。对不上就是问题，请记下来（最好附上截图与 `adb logcat`）。
> 标 ⭐ 的是「不通就等于这个模块没做成」，其余是观感与健壮性。

## 0. 安装与启动

- [ ] ⭐ 安装 `app-debug.apk` 成功，图标与名称是「时间记账」
- [ ] ⭐ 启动不崩，直接进入首页（三个 Tab：首页 / 日历 / 统计）
- [ ] 杀掉进程再打开，数据还在（Room 落库正常）
- [ ] 深色模式下打开，文字与背景都看得清（`values-night` 主题）
- [ ] 系统字体调到最大，界面没有文字被截断或被按钮盖住

## 1. 系统感知（需求六节）—— 最需要验证的一块

- [ ] ⭐ 首页顶部出现「让系统自动记账」卡片，点「去授权」能跳到系统设置
- [ ] ⭐ 设置列表里**能找到「时间记账」**（说明 `PACKAGE_USAGE_STATS` 声明生效）
- [ ] ⭐ 打开开关后回到 App，卡片自动变成「系统感知」（不需要手动刷新）
- [ ] 点「重新读取」，几秒内出现「读出 N 段时间…」
- [ ] ⭐ 时间轴出现今天的使用记录，时间是**合理的**（不是全 0、不是全 24 小时）
- [ ] ⭐ 记的时间与「设置 → 数字健康」里的数据大致吻合
- [ ] App 名显示成中文名（如「微信」）而不是 `com.tencent.mm`
      → 若显示包名，说明 `<queries>` 或应用名解析有问题，记下来
- [ ] 首页「去归类」按钮只在有未归类 App 时出现
- [ ] 归类页按最近使用排序，能正确显示「2 小时前用过 · 打开 8 次」
- [ ] ⭐ 归类一个 App（例如微信 → 社交）后，重新读取，该 App 的记录变成**已归类**（不再待确认）
- [ ] 归类页选「两个都不选」保存后，该 App 从「待归类」移到「已处理」，显示「已确认：不归类」
- [ ] ⭐ 手动记一笔覆盖某个时段，再看系统记录：**系统不会覆盖你的记录**，
      首页状态里会出现「N 段与你的记录重叠，以你的记录为准」
- [ ] 在系统设置里**关掉**「使用情况访问」再回到 App：卡片变回「去授权」，且不崩
- [ ] 跨天验证（第二天早上打开）：昨天的记录还在，时间轴没有缺一段
      → 凌晨 2 点左右用过手机的话，那一段应该记在**昨天**（逻辑日 04:00~次日 04:00）
- [ ] 长时间挂后台后回来，数据自动刷新（回到前台会重读一次）

## 2. 手动记录

- [ ] ⭐ 「记一笔」→ 选活动 + 时长 → 保存后时间轴立刻出现这一行
- [ ] 点时间轴任意一行 → 编辑框弹出，起止时间**是这条记录的完整起止**
      （跨 4:00 的记录不该只显示当天那一段）
- [ ] 改时间、改分类、改备注 → 保存后时间轴与统计都跟着变
- [ ] 把结束时间改到早于开始 → 出现「会跨过午夜」提示，保存后时长正确
- [ ] 把起止改成同一时刻 → 提示「只记次数的记录」；时间轴上显示「记了一笔」而不是 0 分钟
- [ ] 次数填 `abc` / `-1` → 保存按钮不可用，并给出原因
- [ ] 删除这一笔 → 二次确认 → 删除后时间轴与统计都更新
- [ ] 跨午夜编辑：23:30–01:00 的记录保存后仍然正确（不是 24 小时）

## 3. 时间轴与事后确认（需求三节 C）

- [ ] ⭐ 首页「待确认」旁点「去确认」，列出系统推测的记录（按记录，不是按时间段）
- [ ] 一键确认一条 → 该条从列表消失，时间轴上不再是弱化显示
- [ ] 「全部确认」（多条时才出现）一次确认全部
- [ ] 「修改」→ 改分类/备注后确认
- [ ] 「缺失时间」里点「补记」→ 生成一条手动记录，缺口消失
- [ ] 只列出 10 分钟以上的缺口（更短的追问太吵）
- [ ] 被手动记录整段覆盖的推测记录**不再出现在待确认里**（没什么可确认的）

## 4. 计划 vs 实际（需求五节）

- [ ] ⭐ 首页「课表」→ 新建一条每周课程（名称、星期、起止）→ 首页出现「计划 vs 实际」
- [ ] 当天有该课程时，「照计划做了」的时长正确
- [ ] 建一条跨夜课程（23:30–01:00）→ 提示「跨夜」，两天的对比都对
- [ ] 停用一条课程 → 不再计入对比，但历史记录不受影响
- [ ] 晚上 22:00 上课的记录是否正确算在当天（04:00 边界）

## 5. 复盘与统计

- [ ] 日历 Tab：月视图有网格、每格有小时数与强度条、今天有标记
- [ ] 目标完成情况显示成 `2/3`
- [ ] 翻月、点「今天」都能正确回到当月/今天
- [ ] 点某一天 → 下方出现该天的时间轴与分类时间
- [ ] 统计 Tab：周/月/年切换、前后翻期、「本期」都能用
- [ ] 趋势柱状图：周 7 根、月按天（每 5 天一个标签）、年 12 根
- [ ] 分类排行、活动排行、目标完成率显示正确

## 6. 目标与分类

- [ ] ⭐ 新建目标（时长 / 计数 / 频次 × 每日 / 每周 / 每月）都能保存
- [ ] 目标值填 0 或负数 → 保存按钮不可用
- [ ] 只选活动不选分类 → 允许保存
- [ ] 新建分类与活动、改颜色、归档、恢复都正常
- [ ] 归档的分类不出现在选择器里，但历史记录的名字还在

## 7. 提醒（需求十二节）—— 最需要真机的一块

- [ ] ⭐ 首次启动会请求通知权限（Android 13+）；拒绝后 App 正常工作（不崩、不重复问）
- [ ] 中午 / 晚上两个时间点能收到通知（非精确，可能晚几分钟，属正常）
- [ ] ⭐ 凌晨 4:00 那条是**静默**的（无声音、无震动）
- [ ] 通知文案里包含未完成目标、待确认条数
- [ ] ⭐ **重启手机**后提醒仍然会来（`BootReceiver` 重新安排了闹钟）
- [ ] 在系统设置里关掉通知 → 提醒不出现但不崩

## 8. 数据与健壮性

- [ ] 用几天后 App 不卡、打开速度没有明显变化
- [ ] 长时间使用后数据库不异常增长（`usage_events` 有 60 天保留策略）
- [ ] 修改系统时间 / 跨时区后，时间轴不错乱（记录用绝对时间戳）
- [ ] 手机休眠一晚，第二天打开数据能补上

## 走查时怎么取证据

```bash
# 崩溃与异常
adb logcat -d *:E | Select-String timeledger

# 看数据库（需要 run-as 或 root）
adb shell run-as com.timeledger.app ls databases

# 清空数据重来一遍
adb shell pm clear com.timeledger.app
```

遇到问题时，README 的「已知局限」与各模块的决策条目里，
很可能已经写清了「为什么会这样」—— 先查那里，再判断是缺陷还是设计取舍。
